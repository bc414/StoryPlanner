# V1 archive mining — per-session protocol

The instrument (voice attribution) is mechanical and validated; the reading is judgment. This
skill keeps every session that reads archive notes on the same method. Which sessions run,
in what order, and how their outputs combine is the WU's business:
`docs/v3-framework/WU1.4-execution-plan.md`. Decisions here are Brian's, dated 2026-09-02.

## The evidence set

`docs/v3-framework/WU1.4-v1-scene-instincts/attribution.csv` — one row per non-Paratext
archive note, regenerated by one command, never hand-edited:

```
dotnet run --project tools/StoryPlanner.VoiceAttribution -c Release -- \
  "C:/Users/Brian/Desktop/TLTT v1 Archive.storyplan" "C:/Users/Brian/Desktop/TLTT Lineage.db" \
  --snapshots "source_material_references/v1 sqlite" \
  --out docs/v3-framework/WU1.4-v1-scene-instincts/attribution.csv --exclude-story Paratext
```

Per row: the note text, `Label`, `Role`, origin id/date, `Sources`, `MatchedSpans` (character
offsets of every model-role run), `PlanFirst` / `EchoCandidate` / `EchoedBy`, `FirstSnapshot`,
`SourceWindow`. Column semantics and thresholds: `tools/StoryPlanner.VoiceAttribution/README.md`.
Brian's census view is `tools/StoryPlanner.VoiceAttribution/scan.html` (drop the CSV on it).

**Read the CSV by script, never whole** (~1.7M tokens). Counts come from a python/sqlite pass;
a specific row's evidence comes from its `OriginId` via `get_lineage` — the 80-word
`SourceWindow` is proof of the match, not enough to settle whose idea something was.

## Labels and what they mean for reading

| Label | Meaning | Read as |
|---|---|---|
| verbatim / edited-paste (role model) | the note is an AI paste, whole or with cuts | Gemini's proposal; adoption unknown |
| framed-paste (role model) | a paste plus ≥6 uncovered words of Brian's | bold = proposal; plain = Brian's (the frame may be a stance toward the proposal or a design of its own — decide per note) |
| fragment (role model) | one lifted sentence (≥8 words) in Brian's note | Brian's design with a borrowed phrasing |
| phrase | shared phrasing under 8 words | Brian's; not attribution |
| none / short | no captured source / under 6 words | Brian's |
| any label, role brian | matched Brian's own prompt | Brian's |
| PlanFirst / Echo | an AI source matched but the plan had the text first / the model was citing the plan | Brian's; the response id is provenance, not a second author |

A design pattern found only in bold is recorded as *proposed*. It becomes *Brian's instinct*
only when a plain note at the same locus carries it, or when Brian's edits to the paste kept it.
Stitched notes (`Sources` ≥ 2): the arrangement is Brian's even where no sentence is.

Pastes (verbatim + edited + framed) and lifts (fragment) are counted separately and never
summed; phrase is disclosed and never counted.

## The reading view

```
  --render <scratchpad dir> --arcs "1-5,6-9,10-13,14-18,19-22,23-26,27-32" \
  --manifest <artifact dir>/read-manifest.md
```

One markdown per arc (Brian's boundaries: 1–5 grimdark opening, 6–9 hopepunk start with the
end of Sabotage as thesis, 10–13 split and reunion, 14–18, 19–22, 23–26, 27–32) plus Aris, in
chapter → plot point → link order. Prefix per note: `[id | label | origin layer/role date id
flags | first snapshot]`. **Bold in the render means AI text and nothing else**; PlanFirst /
Echo rows render plain. Paratext is not rendered. The manifest is the record of what was read
and goes in the artifact directory; the render itself lives in the scratchpad.

Subject files come from `--subjects <ids> --subject-types "Deferred for a plot point,Deferred
until chapter notes"`: each subject's notes plus its scene-link list pointing back into the
arcs. A session reads subject files only if its plan says so.

## Reading protocol

- **Unit of attention: the plot point or link.** Read all of a plot point's notes together,
  then each link's notes, then ask what design — if any — the scene carries. Twenty fragments on
  one plot point are one scene's design.
- **Discovery-first.** The hypothesis list and the WU card's named checks stay closed during
  the read. Patterns emerge from the notes; nothing is searched for.
- **Records, not prose.** After each arc, write one working file (scratchpad, one `Write`,
  never edited) of locus-level records in exactly this shape, one per line:

  ```
  pp:107 | 704;710;720 | model,brian | dream/psychological-evidence | [720] You had a dream about choosing to collaborate and the shame
  link:1171 | 3066;3067;3068;3069;3070 | brian | dramatic-irony/cross-character | [3068] He thinks Applejack is speaking in coded metaphors
  pp:107+pp:412 | 2467;5210 | brian | revelation-sequencing | [2467] The real truth not revealed until much later
  ```

  Fields: locus (`pp:` / `link:` / `chapter:` / `subject:`; `+` joins a setup to its payoff) ·
  note ids · voices of those ids from the CSV · one-line pattern name (free text; normalised
  later) · one verbatim excerpt with its id. No summaries, no conclusions, no hypothesis ids.
- **A plot point with nothing design-shaped gets no record.** Common, and not a gap.
- **Blindness.** A reading session opens only the render, the CSV (by script), and lineage
  (by id). It does not open another session's records or synthesis unless its plan says so.
- **Verification before use.** Any classification a deposit will rest on is verified by
  reading the full lineage turn (`get_lineage <OriginId>`) or the neighbouring notes first.

## What none of this does

Migrate anything. Propose tracks or display questions. Judge whether an instinct is correct.
Decide whether a pasted proposal was adopted (that is a reading, made per note, from plain
neighbours and edits). Write to any `.storyplan`. Run the attribution tool on the v2 working
plan — that is the lint report, a later activity with the same tool.
