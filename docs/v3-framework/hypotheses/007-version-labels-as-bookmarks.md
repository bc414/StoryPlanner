## Hypothesis

V0-v3 are point-in-time configurations of the four pipeline factors, not
paradigm shifts, and each era's outcomes should be retroactively decomposed
along individual factor changes using dated lineage evidence.

## Record

- created | 2026-08-31T19:30: Follows from the four-factor decomposition
  (hypothesis 006). If the factors vary independently, then version labels are
  convenient bookmarks on a continuous evolution, not paradigm boundaries. The
  "v1 shift" was actually several concurrent factor changes: model (none →
  Gemini), data (Google Doc → plan database), harness (manual editing → WPF
  app), instructions (none → implicit Gemini defaults). Some factor changes
  don't align with version boundaries at all — Claude web chat arrived late in
  v1's life (Apr 9, 2026), changing the model factor without a version bump.
  The retroactive decomposition — dating individual factor changes using
  lineage and conversation evidence rather than attributing them to version
  boundaries — is how this hypothesis gets tested and how the version history
  becomes more useful as analytical infrastructure.
